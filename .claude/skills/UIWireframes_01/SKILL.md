# UIWireframes_01 — 표준 양식 화면설계서 생성

입력(서비스 설명 · 화면 목록 · 기능 · 이 저장소의 프로젝트 내용)을 `template.pptx` 양식에 맞춰 채운 `.pptx`로 만든다.
양식의 디자인(레이아웃 · 색 · 도형 · 표 구조)은 바꾸지 않고 **텍스트만 교체**하며, 필요 없는 슬라이드는 빼고, 새 화면이 필요하면 기존 화면 정의 페이지를 복제해서 쓴다.
`proposal_01`(제안서)과 **같은 ID 체계**(FN · REQ · 화면 ID)를 쓰므로, 제안서가 있으면 그 ID를 그대로 가져온다.

## 파일
- `template.pptx` — 원본 양식 (수정 금지, 항상 복사본으로 작업)
- `slide_map.md` — 50장 슬라이드별 제목 · 형태 + 양식 내장 규칙. **작업 전 반드시 읽는다**
- `scripts/dump_text.py` — 텍스트 덤프. `--runs N`으로 슬라이드 N의 텍스트 인덱스를 본다
- `scripts/build_deck.py` — 슬라이드 선택 + 텍스트 교체 + 정리 + 검증을 한 번에 (사용법은 파일 상단 주석)
- PPTX 구조 편집(슬라이드 복제 `add_slide.py` · 정리 `clean.py` · 검증 `validate.py`)은 `anthropic-skills:pptx` 스킬 것을 쓴다. 필요한 순간에 그 스킬을 로드한다.

## 사전 점검 (작업 시작 전에 매번 먼저 실행 — 필요한 것이 없으면 설치하고 진행한다)
1. `anthropic-skills:pptx` 스킬을 로드한다. 로드되지 않으면 사용자에게 "PPTX 편집 스킬이 없어 정리 · 검증을 생략한다"고 알리고, 결과물 보고에도 그 사실을 적는다 (`build_deck.py`는 이 경우 경고만 내고 생성은 계속한다).
2. 필요한 Python 패키지를 확인한다:
   ```bash
   python -c "import defusedxml" || pip install defusedxml
   ```
   - 권한 오류면 `pip install --user defusedxml`로 재시도한다
   - 이후 실행 중 `ModuleNotFoundError: No module named 'xxx'`가 나오면 **그 모듈을 `pip install xxx`로 설치하고 같은 명령을 다시 실행**한다 (예: `lxml`)
   - 설치가 끝내 실패하면 원인(권한 · 네트워크 · 사내 정책)을 사용자에게 알리고, 사용자가 직접 실행할 명령을 안내한다
3. 설치한 패키지가 있으면 최종 보고에 한 줄로 적는다.

## 절차

### 1. 입력 정리 (생성 전 사용자 확인)
아래 항목을 뽑아 **표로 요약해 보여주고 확인**받는다. 비어 있는 핵심 항목은 질문한다.
- 고객사 · 서비스명 · 작성 부서 · 작성자 · 날짜 · 문서 단계(기본 / 상세 설계)
- **화면 목록**: 화면명 · 화면 ID · 유형(단일 / 목록 / 폼 / 팝업 / 대시보드 / 모바일) · 대상 역할 · 연결 기능(FN) · 요구사항(REQ)
- 메뉴 구조 · 역할(권한 매트릭스) · 화면 이동
- 화면별 요소와 동작 규칙 (와이어프레임에 넣을 것)
- 생성 범위: **전체(50p)** / **기본형**(표지 · 개요 · 설계 기준 · 핵심 화면 N개 · 마무리) / **화면 정의만**

입력에 없는 값은 지어내지 않는다. `[대괄호]` 자리표시자는 그대로 두고 마지막에 "미확정 항목"으로 보고한다.

### 2. 슬라이드 매핑
- 화면 하나 = 화면 정의 페이지 하나. 화면 유형에 가장 가까운 원본 페이지를 고른다
  (로그인 21 · 챗봇 20/22 · 대시보드 23 · 목록+상세 24 · 폼 25 · 모바일 26 · 팝업 27 · 검색 28 · 카드목록 29 · 탭+폼 30 · 알림 31 · 공지 32 · 관리자 34/35 · 오류 36)
- 같은 유형 화면이 여럿이면 원본 페이지를 `add_slide.py`로 복제한다 (복제는 **텍스트 편집 전에** 모두 끝낸다)
- 간지 · 목차 · 문서 구성의 장 번호와 제목 번호(`Ⅲ-N.`)는 최종 구성에 맞춰 연속되게 다시 매긴다
- 화면 목록(7) · 메뉴 구조(8) · 화면 이동(9) · 권한(10) · ID 체계(18)는 화면 정의와 **일치**해야 한다 (ID 누락 · 중복 금지)

### 3. 화면 정의 페이지 채우기 (핵심)
각 페이지는 `메타 → 와이어프레임 → 번호 설명표 → 정책 · 논의` 구조를 유지한다.
1. 메타: 화면 ID · 경로(`대메뉴 > 화면`) · 대상 역할
2. 와이어프레임: 도형 안의 텍스트(버튼 · 라벨 · 샘플 데이터)를 해당 서비스의 실제 항목으로 교체. 도형을 새로 그리지 않는다. 남는 요소는 도형 그룹째 삭제, 부족하면 같은 종류 도형을 복제
3. 번호 마커(①②③…)와 설명표 번호는 1:1. 요소를 지우면 번호를 다시 매긴다
4. 설명표: 요소명 + 동작 · 표시 규칙(입력 길이 · 활성 조건 · 예외 · 권한)을 구체적으로
5. 하단 `정책: … | 논의 필요: …` 한 줄: 보안 · 개인정보 · 로그 정책과 미결 사항
6. 샘플 데이터의 개인정보는 마스킹 표기(`홍○○`, `hong***`)를 유지한다

### 4. 생성
```bash
python scripts/dump_text.py template.pptx --runs 20      # 교체할 텍스트 인덱스 확인
# spec.json 작성 → keep(남길 슬라이드 · 순서) + edits({슬라이드:{인덱스:새 텍스트}})
python scripts/build_deck.py spec.json                    # 생성 + 정리 + 검증
```
- 슬라이드 복제가 필요하면 먼저 `anthropic-skills:pptx`의 `add_slide.py`로 복제본을 만든 뒤 그 파일을 template로 지정한다
- 문체는 양식과 같게 명사형 · 간결체. 한 칸에 들어갈 길이로 쓰고, 넘치면 문장을 줄인다 (폰트 축소 금지)

### 5. 검수 · 결과물
- 양식 Ⅴ-5의 **설계 검수 체크리스트**를 스스로 통과시킨다: 화면 ID 중복 없음, 번호 마커 ↔ 설명 일치, 5개 상태 정의, 권한 · 개인정보 명시, 개정이력 갱신
- 남은 자리표시자 확인: `python scripts/dump_text.py out.pptx | grep -E "\[[^]]*\]|YYYY|XXX"`
- 렌더링 가능한 환경이면 이미지로 겹침 · 넘침을 확인한다. **불가능한 환경이면 그 사실을 사용자에게 알린다** (이 양식은 도형 위에 글자가 올라가는 구조라 넘침 확인이 특히 중요)
- 저장: 프로젝트 루트 `wireframes/[서비스명]_화면설계서_YYYYMMDD.pptx`
- 보고: 파일 경로 · 최종 장수 · 만든 화면 목록(ID) · **미확정 자리표시자(슬라이드 번호별)** · 확인하지 못한 항목
