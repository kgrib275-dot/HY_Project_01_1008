# MeetingNote — 표준 회의록 생성 (docx + html)

회의 내용(녹취록 · 메모 · 대화 텍스트)을 읽고 구조화해서, **같은 서식의 Word 파일과 HTML 파일 두 개**를 만든다.
서식은 팀 표준 회의록(`회의록_YYYYMMDD`)과 동일하다: 남색(#1E3A5F) 제목 · 맑은 고딕 · 회색 라벨 표 · 번호 섹션.

## 파일
- `scripts/build_meeting_note.py` — JSON → `.docx` + `.html` 생성 (표준 라이브러리만 사용)
- `templates/base.docx` — Word 서식 패키지(스타일 · 번호매기기, **본문은 비어 있음**). 수정 금지
- `templates/meeting_note.css` — HTML 서식
- `examples/sample_spec.json` — 입력 JSON 예시(더미 내용). 항목 설명은 스크립트 상단 주석 참조

## 절차

### 1. 입력 읽기 · 확인
- 입력: 녹취록 · 메모 · 전사 텍스트 또는 파일 경로(txt · docx · md 등). 파일이면 먼저 읽는다.
- 사용자가 따로 주지 않은 **일시 · 장소 · 참석자 · 작성일**이 입력에 없으면 임의로 채우지 말고 한 번에 묻는다. (답이 없으면 `[일시 확인 필요]`처럼 비워 두고 7번 "확인 필요 사항"에 적는다)
- 특정 기한 · 담당이 대화에 없으면 비워 두거나 추정 표시를 한다.

### 2. 구조화 — 아래 7개 섹션 (값이 없는 섹션은 자동으로 빠지고 번호가 다시 매겨진다)
| 키 | 섹션 | 작성 기준 |
|---|---|---|
| `overview` | 1. 회의 개요 | 표: 회의명 · 일시 · (장소) · 참석 · 작성일 |
| `purpose` | 2. 회의 목적 | 한두 문장 ("~을 합의한다." 식) |
| `discussion` | 3. 주요 논의 내용 | 소주제 `heading` + `bullets`. 시간 순이 아니라 **주제별**로 묶는다 |
| `decisions` | 4. 결정 사항 | 합의된 것만. 논의 중인 것은 3번에 둔다 |
| `actions` | 5. Action Items | 내용 · 담당 · 기한. No는 자동 |
| `risks` | 6. 리스크 및 이슈 | 리스크/이슈 ↔ 대응 방향 |
| `confirm` | 7. 확인 필요 사항 | 추정한 내용 · 불분명한 부분 · 양식 관련 메모 |

### 3. 작성 원칙
- **말하지 않은 내용을 만들지 않는다.** 수치 · 날짜 · 고유명사는 원문 그대로, 확정되지 않은 수치는 "(미확정)" 표기
- 문체는 개조식 · 명사형 종결 (`~함`, `~필요`, `~한다`). 한 항목 한 줄~두 줄
- 발화자 이름이 없으면 소속 · 역할 기준으로 쓴다 (`A사: …`, `개발팀 의견: …`)
- 녹취 인식 오류로 불분명한 표현은 추정 또는 일반 표현으로 쓰고 **7번에 "확인 필요"로 명시**
- Action Item의 담당 · 기한을 대화 흐름으로 추정했다면 7번에 "추정이므로 확정 필요"를 적는다
- 개인 평가 · 감정적 표현 · 잡담은 제외하되, 의사결정에 영향을 준 의견은 남긴다

### 4. 생성
```bash
# 1) 위 구조를 spec.json 으로 저장 (examples/sample_spec.json 형식)
# 2) 실행
python scripts/build_meeting_note.py spec.json --out-dir "저장할 폴더"
#    --format docx | html | both(기본)
```
- 파일명은 `date`가 있으면 `회의록_YYYYMMDD`, `basename`으로 직접 지정 가능
- 저장 위치: 사용자가 지정한 폴더. 지정이 없으면 프로젝트 루트 `meetings/` (git에 올라가지 않음)

### 5. 점검 · 보고
- 생성 직후 확인: 두 파일 모두 만들어졌는지, 섹션 번호가 연속인지, `[대괄호]` 자리표시자가 남았는지
- 이 PC에는 Word가 없을 수 있다. **docx를 Word에서 직접 열어 본 것이 아니라면 그렇게 보고**한다 (HTML은 브라우저로 열 수 있다)
- 사용자에게 보고할 것: 파일 경로 2개 · 만든 섹션 / 생략한 섹션 · **7번에 적은 확인 필요 사항 요약** · 추정으로 채운 담당 · 기한

## 주의
- 회의 내용에는 고객사 · 계약 · 보안 정보가 포함될 수 있다. 외부 서비스에 보내지 않고, 결과물을 git에 올리지 않는다 (`meetings/`는 `.gitignore`에 포함)
- 양식 자체를 바꾸려면 `templates/`를 수정하고 PR로 공유한다
